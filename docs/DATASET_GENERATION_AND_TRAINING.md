### Local ↔ GCS Dataset Sync

The repo keeps raw/public data under `training-data/` (gitignored). Mirror that tree into `gs://ssis-training-1776624951/datasets/` so Spot VMs can `gsutil` download exactly what they need.

```bash
# From your local workstation (once files are downloaded into training-data/)
gsutil -m rsync -r training-data/ gs://ssis-training-1776624951/datasets/

# On the Spot VM (keeps training-data/ in sync with bucket)
mkdir -p training-data
gsutil -m rsync -r gs://ssis-training-1776624951/datasets/ training-data/
```

This avoids `FileNotFoundError` during training because every script reads from an explicit `training-data/p*` path (raw data) or from `ai/...` (preprocessed outputs generated by `scripts/preprocess_training_data.py`).

## One-Time GCP Setup (~15 minutes)

> **Why venv?** The GCP deep learning VM images ship with a system Python that `gsutil`, `nvidia-smi`, and the CUDA toolkit depend on. Installing training packages directly into it can silently break these tools. A virtualenv isolates your training deps while keeping the system Python intact. It also makes the environment reproducible across VM restarts/preemptions.

SSH into your Spot VM:

```bash
# 1. System dependencies
sudo apt update && sudo apt install -y git python3-pip python3-venv hdf5-tools

# 2. Create isolated Python venv (REQUIRED — do NOT pip install into system Python)
python3 -m venv ~/ssis-env
source ~/ssis-env/bin/activate

# 3. ML + Physics stack (CUDA 12.1)
pip install --upgrade pip
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install numpy pandas h5py scipy scikit-learn tqdm tensorboard matplotlib
pip install torch-geometric pymsis poliastro google-cloud-storage onnx wandb

# 4. Clone repo
git clone https://github.com/adityamourya-hub/idex.git && cd idex
mkdir -p checkpoints weights logs training-data

# 5. (Local machine) Mirror training-data/ → GCS datasets bucket
# gsutil -m rsync -r training-data/ gs://ssis-training-1776624951/datasets/

# 6. (On VM) Pull down the same tree before training
gsutil -m rsync -r gs://ssis-training-1776624951/datasets/ training-data/
```

**IMPORTANT — activate venv on every new SSH session**:
```bash
source ~/ssis-env/bin/activate && cd ~/idex
```

**Preemption Rule**: Every 5 epochs (or on SIGTERM), checkpoints auto-sync to GCS. On preemption, restart the VM and re-run — training resumes from the latest checkpoint.

## Phase P0: Neural Atmosphere Operator (Weeks 1–2)

**Goal**: Atmospheric density model with <0.5% error vs NRLMSISE-00.

### Dataset Generation

Generate 10M synthetic samples using NRLMSISE-00 as the oracle and store them under `training-data/p0/synthetic/`:

```bash
source ~/ssis-env/bin/activate && cd ~/idex

# Ensure output directory exists
mkdir -p training-data/p0/synthetic

# Generate dataset only (saves to HDF5, no training)
python3 scripts/train_neural_atmosphere.py --generate-only \
  --num-samples 10000000 \
  --output-path training-data/p0/synthetic/train_data.h5

# Optionally sync to GCS for reuse across VMs
gsutil -m rsync -r training-data/p0/synthetic/ gs://ssis-training-1776624951/datasets/p0_atmosphere/synthetic/
```

### CHAMP/GOCE Real-World Validation Data

The synthetic training data must be validated against real accelerometer-derived thermospheric densities to meet the P0 quality gate (<0.5% density error).

**Step 1 — Download CHAMP/GOCE data (on your local machine)**:

- **TU Delft Thermosphere Database**: [thermosphere.tudelft.nl](http://thermosphere.tudelft.nl/) — CHAMP (2001–2010) and GOCE (2009–2013) accelerometer densities
- **NASA Earthdata / TU Delft**: CHAMP/GOCE data comes as native `.txt` (space-delimited with `#` comment headers, Fortran `E-` notation, altitude in **meters**, density in `kg/m³`)
- Typical files: `goce_density_2009.txt`, `champ_density_2000.txt` (~50–200 MB per year)

**Step 2 — Upload to GCS (once, from local machine)**:
```bash
# Create validation data folder in bucket
gsutil mb -p YOUR_PROJECT_ID gs://ssis-training-1776624951/validation/ 2>/dev/null || true

# Upload CHAMP/GOCE .txt files
gsutil -m cp champ_density_*.txt gs://ssis-training-1776624951/validation/champ_goce/
gsutil -m cp goce_density_*.txt gs://ssis-training-1776624951/validation/champ_goce/

# Keep bucket mirror in sync with your repo copy
mkdir -p training-data/p0/validation
cp champ_density_*.txt training-data/p0/validation/  # adjust paths as needed
gsutil -m rsync -r training-data/p0/validation/ gs://ssis-training-1776624951/datasets/p0_atmosphere/validation/
```

**Step 3 — Download to Spot VM (before validation)**:
```bash
source ~/ssis-env/bin/activate && cd ~/idex

# Download validation data from GCS to VM local disk
mkdir -p training-data/p0/validation
gsutil -m rsync -r gs://ssis-training-1776624951/datasets/p0_atmosphere/validation/ training-data/p0/validation/
```

### Training

```bash
source ~/ssis-env/bin/activate && cd ~/idex

# Train from pre-generated HDF5 dataset
python3 scripts/train_neural_atmosphere.py \
  --data-path training-data/p0/synthetic/train_data.h5 \
  --epochs 100 --batch-size 8192 --lr 1e-3 --device cuda

# Or generate + train in one shot (for smaller datasets)
python3 scripts/train_neural_atmosphere.py \
  --num-samples 100000 --epochs 100 --device cuda

# Upload weights to GCS
gsutil cp weights/neural_atmosphere_final.pth gs://ssis-training-1776624951/weights/p0_atmosphere/
gsutil cp weights/neural_atmosphere.onnx gs://ssis-training-1776624951/weights/p0_atmosphere/
```

**Training script**: `scripts/train_neural_atmosphere.py` — trains a Fourier Neural Operator (FNO) with physics loss:
```
L = ||log(ρ_nn) - log(ρ_msis)||² + λ_phys ||∂P/∂h + ρg||²
```

**FNO architecture**: `q/core/hno_pytorch.py`

**Quality gate**: Density error < 0.5% on CHAMP/GOCE validation set.
**Estimated time**: 4–7 days on L4 Spot (~$0.4–0.8/hr).

### Validation

**Option A — Synthetic oracle validation** (quick, after training):


**Step 3 — Generate synthetic orbital trajectories** (5M samples):


The scenario generator produces 64-dim graph-native samples with:
- Position/velocity in canonical units (DU/TU, µ=1.0)
- SE(3)-equivariant features (spectral residuals, fractional drag, MGE threat score)
- Edge features for GATv2 attention (relative pos/vel/distance)
- 4-class orbit labels (LEO/MEO/GEO/HEO)

## Phase P2: Hypersonic + Neural SINDy (Weeks 5–6)

**Goal**: Discover unknown forces/maneuvers for ballistic/HGV threats. Position error < 50m after 60s prediction.

### Dataset Generation

```bash
source ~/ssis-env/bin/activate && cd ~/idex

# Ensure local mirrors exist
mkdir -p training-data/p2/raw training-data/p2/processed
gsutil -m rsync -r gs://ssis-training-1776624951/datasets/p2_hypersonic/ training-data/p2/ || true

# Generate 3M hypersonic trajectories (3-DoF/6-DoF with zero-day maneuvers)
python3 sda-train/scripts/gen_reentry_storms.py \
  --n_samples 3000000 \
  --include_zero_day_maneuvers \
  --output training-data/p2/raw/hgv_storms/

# Also generate reentry scenarios with geomagnetic storm conditions
python3 sda-train/scripts/gen_reentry.py \
  --n_samples 500000 \
  --output training-data/p2/raw/reentry/

# Keep bucket in sync so future runs can reuse
gsutil -m rsync -r training-data/p2/raw/ gs://ssis-training-1776624951/datasets/p2_hypersonic/raw/
```

### Training

```bash
source ~/ssis-env/bin/activate && cd ~/idex

# HGV Physics-informed HNO
python3 ai/v3/hgv_phno.py \
  --data training-data/p2/raw/hgv_storms/ \
  --epochs 60 --device cuda

# Neural SINDy for maneuver discovery (Go-side integration)
# The SINDy discoverer in pkg/physics/sindy.go operates on residuals:
#   r(t) = ẍ_observed - ẍ_keplerian
# Training the neural SINDy latent encoder:
python3 ai/v3/eso_neural_sindy.py \
  --data training-data/p2/raw/hgv_storms/ \
  --epochs 60 --device cuda
```

**SINDy sparsity** is enforced via `compute_sparse_loss` in `ai/neural_ode/train.py`:
```
L_sparse = λ · mean(max(0, ||z_t||₁ - ε_noise))
```
This prevents micro-thrust hallucination — the network cannot use tiny latent adjustments to fit sensor noise.

**Quality gate**: Position error < 50m after 60s prediction horizon.
**Estimated time**: 4–6 days.
